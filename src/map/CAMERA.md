# Модуль движения и полёта камеры (`cameraRig.js`)

Модуль заменяет `OrbitControls` одним контроллером, который одинаково удобен
и «впритык к планете» (0.5 юнита), и на краю галактики (1 000 000 юнитов).
Ниже — почему он устроен именно так и как его подключать/настраивать.

---

## 1. Шесть решений, из-за которых полёт ощущается правильно

### 1.1 Мультипликативный зум (экспоненциальный долли)

```js
dist *= Math.exp(deltaY * zoomRate)      // колесо
dist *= Math.pow(pinchPrev / pinchNow, zoomTouchRate)   // пинч
```

Один щелчок колеса **всегда** меняет масштаб в одинаковое число раз
(по умолчанию ≈ ×1.17), независимо от текущей дистанции. У `OrbitControls`
зум линейный (`dist += c`), поэтому вблизи он «прыгает», а вдали «не едет».

Проверено тестом: 5 щелчков дали коэффициент `0.8521` на каждом шаге — без дрейфа.

### 1.2 Скорость пропорциональна масштабу обзора

```js
speed = baseSpeed * dist^speedPower * speedMul * (boost ? 8 : 1) * (fine ? 0.12 : 1)
```

Держа `W`, корабль за секунду пролетает примерно одинаковую **долю** видимого
пространства. При `dist = 2` (у планеты) это ювелирное маневрирование,
при `dist = 400 000` (галактика) — перелёт за секунды. Тест показывает,
что `speed / dist` сходится ровно к `baseSpeed` (1.9) на любом масштабе.

Поверх авто-масштаба — **ручной множитель** ×0.1…×10:
слайдер внизу, клавиши `0…9`, `[` / `]`, а также `Shift` (×8) и `Space` (×0.12).
`Ctrl` сознательно НЕ используется: `Ctrl+W` и подобные — шорткаты браузера,
игрок потеряет вкладку вместо точного манёвра.

### 1.3 Динамические near / far

```js
near = clamp(dist * 0.02, 0.002, 50)
far  = clamp(dist * 3000, 200, 8e8)
```

Пересчёт каждый кадр. Фиксированные `near=0.1 / far=10000` — классическая
причина «кривого» большого пространства: либо z-fighting вблизи, либо обрезанная
галактика вдали. В паре с `logarithmicDepthBuffer: true` у рендерера рабочий
диапазон ≈ 9 порядков. В HUD строка `near / far` показывает это вживую.

### 1.4 Floating origin (перебазировка)

GPU хранит позиции в `float32`: на координатах ~1e6 точность падает до ~0.06
юнита, и объекты начинают «дрожать», когда подлетаешь близко.

Поэтому введены **два пространства координат**:

| Пространство | Где живёт | Точность |
|---|---|---|
| **вселенная** (universe) | данные карты (`sys.pos`), закладки, `ORIGIN` | float64 (JS Number) |
| **рендер** (render) | `camera.position`, `rig.focus` | float32-безопасно (≈0) |

Связь: `render = universe − originShift`. Группа `worldRoot.position = −originShift`,
поэтому **локальные** координаты её детей — это координаты вселенной, и при
перебазировке их трогать не нужно. Когда `|focus| > rebaseThreshold`, мир и камера
сдвигаются на одну и ту же величину — игрок не видит ничего, а счётчик
«Ребазировок» в HUD растёт.

API: `rig.originShift`, `rig.camUniverse`, `rig.focusUniverse`,
`rig.toRender(v)`, `rig.toUniverse(v)`.

> ⚠️ Всё, что передаётся в `rig.flyTo({ position })` и в `rig.setState({ lookAt })`,
> должно быть в **рендер**-координатах. Данные карты конвертируй через `rig.toRender(...)`.

### 1.5 Кадронезависимое демпфирование + инерция

```js
k = 1 - Math.pow(1 - lambda, dt * 60)     // вместо lerp(a, b, 0.1)
```

Обычный `lerp(x, y, 0.1)` внутри `requestAnimationFrame` — баг: на 144 Гц всё
в 2.4 раза «быстрее», чем на 60 Гц. Здесь результат зависит только от `dt`.
Скорость и вращение набираются/гаснут экспоненциально → корабль чувствуется
тяжёлым, а не как курсор мыши (тест `INERTIA` показывает плавное затухание).

### 1.6 Скайбокс привязан к камере

Панорама/туманность масштабом в тысячи юнитов на фиксированной позиции либо
обрезается far-ом, либо «уезжает» при полёте. Риг каждый кадр центрирует
`options.skybox` на камере и масштабирует под текущий `far`, поэтому небо
всегда вокруг игрока на любом масштабе.

## 2. Управление

### Десктоп
| Действие | Клавиши / мышь |
|---|---|
| Орбита вокруг точки фокуса | ЛКМ-драг |
| Панорамирование (сдвиг фокуса) | ПКМ-драг или `Shift`+ЛКМ |
| Зум (мультипликативный) | колесо |
| Полёт в плоскости взгляда | `W A S D` |
| Вверх / вниз | `E` / `Q` |
| Ускоритель ×8 (+ рывок FOV) | `Shift` |
| Точный режим ×0.12 | `Space` |
| Ручной множитель скорости | `0…9`, `[`, `]` |
| Домой | `Home` |
| Снять выбор объекта | `Esc` / клик по пустоте / `✕` |
| Закрыть карточку и взять управление | любая клавиша движения / колесо при открытой карточке |

### Телефон
| Действие | Жест |
|---|---|
| Орбита | 1 палец |
| Зум | пинч |
| Панорамирование | драг центроида двух пальцев |
| Стрейф влево/вправо | джойстик слева |
| Тяга вперёд/назад, высота | кнопки `⇧ ⇩ ▲ ▼` справа |
| Ускоритель / точно | удерживаемые кнопки над шкалой скорости |

Когда выбран объект, появляется переключатель **«вращение объекта / облёт
камерой»** (на десктопе вращение объекта — ЛКМ, облёт — ПКМ; на телефоне режим
выбирается кнопкой, т.к. правой кнопки нет).

## 3. API `createCameraRig(camera, domElement, options)`

```js
const rig = createCameraRig(camera, renderer.domElement, {
    worldRoot,        // группа с миром — нужна для перебазировки
    skybox: map.sky,  // объект, который держим у камеры
    rebaseThreshold: 3e5,
    minDist: 0.8, maxDist: 4e6,
    baseSpeed: 1.9, speedPower: 1.0,
    zoomLambda: 0.16, rotateLambda: 0.5, followLambda: 0.4,
    linearAccel: 9, linearDamp: 6.5,
})
```

| Метод | Назначение |
|---|---|
| `update(dt)` | вызывать каждый кадр **после** обновления мира |
| `setState({position, lookAt, dist, theta, phi})` | мгновенная постановка |
| `flyTo({position, dist, theta, phi, subject, duration, ease, onComplete})` | плавный перелёт; `subject` — лететь **за** движущимся объектом |
| `cancelFlight()` | прервать перелёт (шлёт событие `flightCancel`) |
| `frameObject(obj, {pad, fly, duration})` | вписать объект по bounding sphere |
| `followObject(obj)` / `releaseSubject()` | слежение за орбитой / отпустить |
| `flyHome()` / `setHome()` | домой / запомнить дом |
| `setLocked(v)` | выключить ввод пользователя (перелёт при этом живёт!) |
| `setPaused(v)` | заморозить риг целиком |
| `suppressPointer(ms)` | «не реагируй на указатель» (чтобы клик по объекту не начинал орбиту) |
| `orbitBy(dTheta, dPhi)` | доворот углов (использует objectUse для облёта ПКМ) |
| `setSpeedMultiplier(v)` / `setSpeedStep(i)` / `stepSpeed(±1)` | ручная скорость |
| `setExternalInput({f, r, u, boost, fine})` | ввод от виртуального джойстика |
| `on('update' \| 'speed' \| 'rebase' \| 'flightCancel', fn)` | события для HUD |
| `telemetry()` | снапшот: fps, dist, speed, near/far, focus, rebases… |

Свойства: `focus`, `focusTarget`, `sph`, `sphTarget`, `home`, `vel`,
`originShift`, `camUniverse`, `focusUniverse`, `dist`, `isFlying`, `isLocked`,
`isBoost`, `isFine`, `subject`, `rebases`.

## 4. Как подключается к сцене

Порядок в кадре **важен**:

```js
function animate() {
    requestAnimationFrame(animate)
    const dt = ...
    map.update(dt, rig)        // 1. орбиты и LOD — по актуальной позиции камеры
    interactor.update(dt)      // 2. анимация «старых» объектов (userData.rotationSpeed/orbit)
    rig.update(dt)             // 3. камера — последней, уже по новым позициям
    renderer.render(scene, camera)
}
```

Интеграция с «взял объект в руки» (`objectUse.js`): модуль больше не двигает
камеру сам (`gsap.to(camera.position)` ушёл), а командует ригом:
`flyTo` (подлёт) → `followObject` (компенсация орбиты) → `flyTo` (возврат).
Благодаря этому подлёт и свободный полёт — одна физика, без рывков.

Если у тебя своя сцена (сейчас именно так — `chartMap.js` строит её из твоих GLB):

```js
const rig = createCameraRig(camera, renderer.domElement, { worldRoot })
rig.setState({ lookAt: new THREE.Vector3(...), dist: 500 })
// в кадре: rig.update(dt)
```

Всё остальное (зум, скорость, near/far, перебазировка) работает само.

## 5. Производительность (как карта держит 2500 систем)

* **Звёзды — один `THREE.Points`** с шейдером «постоянного экранного размера»
  (`gl_PointSize` не зависит от дистанции). Не 2500 спрайтов с пересчётом
  масштаба на CPU каждый кадр. Вид галактики = 8 draw calls.
* **Пикинг звезды — аналитический**: проекция в экран и поиск ближайшей к
  курсору (O(N), ~0.2 мс), а не raycast по тысячам мешей. По планетам/солнцу —
  обычный raycaster (их мало).
* **LOD**: планеты, орбиты, свет и подписи создаются только для систем ближе
  `detailRadius` от **камеры** (бюджет 14) и уничтожаются, когда улетел.
* **Подписи** пересчитываются ~6 раз/с (сортировка 2500 элементов недешёвая)
  и держат постоянный размер на экране; на планетарном масштабе гаснут.
* **Секторная сетка** — два слоя LineSegments, которые плавно сменяют друг
  друга по дистанции (как «масштаб» в обычных картах).

## 6. Главные ручки настройки (`RIG_DEFAULTS`)

| Параметр | Смысл | Дефолт |
|---|---|---|
| `baseSpeed` | скорость при `dist = 1` (в долях дистанции/с) | 1.8 |
| `speedPower` | 1.0 = строго масштабно-инвариантно | 1.0 |
| `boostMul` / `fineMul` | Shift / Space | 8 / 0.12 |
| `linearAccel` / `linearDamp` | «масса» корабля (набор / гашение) | 9 / 7 |
| `zoomRate` | шаг зума на единицу deltaY | 0.0016 |
| `zoomLambda` | мягкость зума (0.14 мягко, 0.35 резко) | 0.14 |
| `rotateSpeed` | 1.0 ≈ «взялся за небо и тянешь» | 1.0 |
| `nearScale/farScale` | множители динамического near/far | 0.02 / 3000 |
| `rebaseThreshold` | 0 = выключить перебазировку | 3e5 |
| `bounds` | `{radius, height}` — цилиндр границы мира для фокуса | null |
| `skybox` | объект-панорама: держится у камеры, масштаб под `far` | null |
| `fovBoost` | расширение FOV на ускорителе (эффект рывка) | 12 |
